# Redaction rules

1. `Policy` holds the literal values and the rule fingerprint. `Default` enables built-in detection without file reads. `Load` adds an explicitly selected private-values file. `Apply` returns sanitized text and sorted rule names. `Match` uses the same detectors. Callers apply the policy to text before encoding replies or writing persistent content.
2. The fingerprint covers the rule version, detector expressions, captured value groups and canonical literal set. Adding, removing or changing a value changes the fingerprint. Input order and duplicate values do not. Changes to matching or replacement semantics require a `Version` change.
3. Replacements have the form `[redacted: RULE]`. Overlapping matches become one replacement covering their union. The longest individual match supplies its rule label, with alphabetical order breaking ties. The result reports all matched rule names once. Allowed surrounding text remains unchanged. The matcher stores at most one longest match per input position, then merges overlapping ranges. It checks uncovered original-text gaps again after a replacement creates token boundaries. Each repeated scan covers at least one previously uncovered input byte, so the process terminates. The sanitizer renders markers once after no detector matches remain. Literal validation prevents matches that cross an emitted marker.

| # | Rule | Recognized forms | Limits |
| --- | --- | --- | --- |
| 1 | `aws-access-key` | `AKIA` or `ASIA` followed by 16 uppercase letters or digits | Other Amazon Web Services identifiers are outside this rule |
| 2 | `aws-secret-key` | A 40-character base64-style value assigned with `=` or `:` to `aws_secret_access_key`, `aws-secret-access-key`, `awsSecretAccessKey` or `secret_access_key` | Field names ignore case; standalone values and other field names are outside this rule |
| 3 | `github-token` | `ghp_`, `gho_`, `ghu_`, `ghs_` or `ghr_` followed by 36 letters or digits; `github_pat_` followed by 20 to 255 letters, digits or `_` characters | Prefix and length detection does not validate a token with GitHub |
| 4 | `google-api-key` | `AIza` followed by 35 letters, digits, `_` characters or hyphens | Other Google credential formats are outside this rule |
| 5 | `slack-token` | `xoxb-`, `xoxa-`, `xoxp-`, `xoxr-` or `xoxs-` followed by 10 to 255 letters, digits or hyphens | Other Slack prefixes are outside this rule |
| 6 | `openai-token` | `sk-`, optionally followed by `proj-` or `svcacct-`, then 20 to 512 letters, digits, `_` characters or hyphens | This broad prefix rule can also match another service's similarly shaped token |
| 7 | `private-key` | A Privacy-Enhanced Mail private-key block labeled `PRIVATE KEY`, `RSA PRIVATE KEY`, `EC PRIVATE KEY`, `DSA PRIVATE KEY`, `OPENSSH PRIVATE KEY` or `ENCRYPTED PRIVATE KEY` | A matching end label closes the block. A missing end label redacts the remaining text |
| 8 | `private-value` | Exact, case-sensitive literal strings from the selected control file | No normalization, encoded-value expansion or arbitrary-secret inference |

4. Token rules reject a match embedded in a longer letter, digit, `_` character or hyphen sequence. Assigned secret values also reject a longer base64-style value. Public-key blocks and short prefix examples remain unchanged. The detectors cannot identify every secret or prove that a matched token is active.
5. The control file contains a UTF-8 JSON array of nonempty strings. It may hold at most 10,000 entries and 1,048,576 bytes. Each value may hold at most 4,096 bytes. An empty array enables built-in rules only. Invalid UTF-8, unpaired escaped Unicode surrogates, NUL, malformed JSON and wrong value types refuse with `ErrPolicyInvalid`.
6. A literal cannot occur inside an emitted marker or contain a whole marker. It also cannot begin with a marker suffix or end with a marker prefix. These restrictions prevent replacements from creating another protected literal. For example, `redacted`, `value]tail` and `prefix[` are invalid. Internal brackets such as `internal[bracket]value` remain valid.
7. The path must be absolute and local. The loader rejects missing files, directories, links, multiple hard links, unreadable files and files that fail the platform's private-owner or private-mode checks. It never changes file bytes or permissions. macOS `/tmp`, `/var` and `/etc` use the platform's trusted system aliases. The loader rejects other symlink components. Windows uses the existing platform permission checks, which do not prove inherited access-control-list privacy.
8. Tests use constructed synthetic tokens. `TestRecognizedSecrets` checks every built-in rule with allowed context. `TestSecretNearMatches` retains allowed lookalikes. `TestLiteralOverlapAndFingerprint` checks overlap, Unicode and deterministic policy changes. `TestPrivateValuesCannotCreateMarkerMatches` checks stable replacements. Loader tests cover input bounds, unsafe file forms and unchanged control inputs. Production storage, migration and command-output tests belong to the calling packages.

9. `TestReplacementBoundaryClosure` covers tokens immediately before and after private literals. `TestOverlapAllocationBound` uses 8,192 input bytes and 128 overlapping literals. Five alternating before-and-after pairs measured revised allocations of 309,384 to 346,424 bytes, with a median of 309,384 bytes. Its 1 MiB regression ceiling allows runtime variation and rejects the original allocation of over 172 million bytes. This is an isolated cumulative-allocation check, not a process memory ceiling. `Match` stops at the first match.

10. Doctor reports rule labels retained in sanitized text. One merged replacement can cover several overlapping detections. Doctor lists that replacement label; it does not reconstruct all detectors that matched the original. This also applies to saved notes, whose original protected text is never stored. The sanitizer result exposes all matched rules to its immediate caller.
